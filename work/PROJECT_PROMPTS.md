# Промпты и техническое задание проекта

Этот файл — единый подробный контекст для продолжения разработки финансового дашборда в Google Apps Script. Его можно передать новому исполнителю или использовать как основу для последующих запросов к AI.

## 1. Базовый промпт для работы с проектом

```text
Ты дорабатываешь финансовый веб-дашборд на Google Apps Script, связанный с Google Sheets.

Исходный код находится в папке work. В проекте есть HTML-файлы страниц и .gs-файлы серверной части. Сохраняй существующий тёмный визуальный стиль, русские подписи и текущую структуру API. Не меняй формулы, источники данных и публичные имена функций без явного запроса.

Страницы:
- Дашборд: dashboard.html + gsdashboard.gs;
- Деньги: money.html + gsmoney.gs;
- Прибыль: profit.html + gsprofit.gs;
- Капитал: capital.html + gscapital.gs;
- общие настройки и маршрутизация: gscore.gs, template.html, gstemplate.gs.

Данные поступают из именованных диапазонов Google Sheets:
- rangecash — лист «Деньги»;
- rangeprofit — лист «Прибыль»;
- rangeequity — лист «Капитал».

Перед изменением изучи связанные HTML и .gs файлы. Делай изменения локально и в Apps Script синхронно. После изменения серверной логики запусти соответствующую функцию в редакторе Apps Script и проверь журнал выполнения. Не публикуй новую версию веб-приложения без отдельного явного подтверждения пользователя.
```

## 2. Структура источников

```text
Лист «Деньги» / rangecash:
Дата, Сумма, Вид операции, Счет, Контрагент, Статья, Раздел ОДДС, Направление, Описание.

Лист «Прибыль» / rangeprofit:
Дата, Сумма, Направление, Наименование проекта, Вид операции, Статья ОПиУ, Раздел ОПиУ.

Лист «Капитал» / rangeequity:
Дата, Раздел 1, Раздел 2, Раздел 3, Раздел 4, Сумма.
```

При чтении данных необходимо:

- обрабатывать даты без сдвига часового пояса;
- приводить текст к строке без лишних пробелов при сравнении;
- поддерживать числа из ячеек и текстовые значения с пробелами, запятыми и символом рубля;
- не суммировать остатки денежных средств за разные даты как потоки;
- не учитывать внутренние перемещения денежных средств как доход или расход.

## 3. Единый период на всех страницах

```text
На главной странице пользователь выбирает начало и конец периода.
Выбранные даты должны сохраняться в localStorage и передаваться на страницы «Деньги», «Прибыль» и «Капитал».
При открытии дочерней страницы поля периода заполняются сохранёнными датами автоматически.
Если пользователь меняет период на дочерней странице, новые значения также сохраняются в localStorage.
Нельзя жёстко подставлять 1 января как единственное возможное начало периода.
```

## 4. Формулы показателей

### 4.1. Коэффициент текущей ликвидности

```text
Дата расчёта — последняя доступная дата среза листа «Капитал», не позже выбранной конечной даты.

Текущая ликвидность =
  итог по «Раздел 3» = «Краткосрочные обязательства» /
  итог по «Раздел 2» = «Оборотные активы».

Пример для учебных данных: около 0,08.
```

### 4.2. Cash Buffer

```text
Расход для Cash Buffer — сумма строк листа «Деньги», где:
- Раздел ОДДС = «2. Основная деятельность»;
- Вид операции = «Расход»;
- дата входит в выбранный период.

Среднедневной расход = абсолютное значение расхода / число календарных дней периода.

Чистый денежный поток — итог операций за период. Если в источнике отсутствуют отдельные строки «Остаток», используется накопленный итог операций до конечной даты периода.

Cash Buffer = |чистый денежный поток / среднедневной расход|.

Всегда показывай положительное значение. Для периода 01.01.2023–30.06.2023:
- расход основной деятельности: −75 969 395,07 ₽;
- дней: 181;
- среднедневной расход: 419 720,41 ₽;
- чистый поток: 60 631 480,30 ₽;
- Cash Buffer: 144,4568293.

Важно: не подменяй эту формулу отношением расхода к остатку. Не включай инвестиционную и финансовую деятельность в расход Cash Buffer.
```

### 4.3. Оборачиваемость дебиторской задолженности

```text
D — последняя дата среза «Капитала», не позже выбранной конечной даты.
S — 1 января года даты D.

1. Выручка: сумма листа «Прибыль» с S по D включительно, где «Раздел ОПиУ» = «1.Выручка».
2. ДЗ на конец: сумма листа «Капитал» на D, где «Раздел 3» = «Дебиторская задолженность».
3. ДЗ на начало: сумма на S; при отсутствии записи на S взять ближайшую предыдущую дату. Если данных нет — вернуть понятную ошибку.
4. Средняя ДЗ = (ДЗ на начало + ДЗ на конец) / 2.
5. Коэффициент оборачиваемости = Выручка / Средняя ДЗ.
6. Оборачиваемость в днях = количество дней в периоде / коэффициент.

Если выручка или средняя ДЗ равна нулю, вернуть 0 для коэффициента и дней.
Возвращать коэффициент, дни и фактические даты начального и конечного срезов.
```

### 4.4. Оборачиваемость кредиторской задолженности

```text
Использовать те же D и S, что для ДЗ.

1. Себестоимость: сумма листа «Прибыль» с S по D, где «Раздел ОПиУ» = «2.Себестоимость». Отрицательные числа брать по модулю.
2. КЗ на конец: «Раздел 3» = «Кредиторская задолженность» на дату D.
3. КЗ на начало: точная дата S либо ближайшая предыдущая дата; при полном отсутствии данных вернуть ошибку.
4. Средняя КЗ = (КЗ на начало + КЗ на конец) / 2.
5. Коэффициент = Себестоимость / Средняя КЗ.
6. Дни = количество дней в периоде / коэффициент.

Если себестоимость или средняя КЗ равна нулю, вернуть 0 для обоих показателей.
```

## 5. Требования к интерфейсу

```text
- Оформление: тёмный финансовый дашборд.
- Во всех карточках и диаграммах денежные величины отображаются как «млн руб.», относительные — как «%».
- Для Cash Buffer показывается положительное число без знака минус.
- На главной странице для «Чистый денежный поток», «Чистая прибыль», «Рентабельность по ЧП» и «Собственный капитал» нужна подпись динамики относительно предыдущего месяца: зелёная стрелка вверх при росте, красная вниз при снижении.
- В карточках оборачиваемости ДЗ и КЗ крупным числом показываются дни; в подписи — коэффициент в разах и фактические даты срезов.
- Размер числа дней в карточках ДЗ и КЗ должен быть таким же, как у ROE и других обычных карточек. Использовать правило:
  .dashboard-card-value.dashboard-turnover-days {
    font-size: clamp(21px, 2.6vw, 30px) !important;
  }
- На страницах «Деньги», «Прибыль» и «Капитал» рядом с текстом загрузки должен быть видимый анимированный индикатор.
- В диаграмме «Поток по направлениям» на странице «Деньги» нужна цветовая шкала: отток — красный, приток — бирюзовый/зелёный.
```

```text
2. Выполни в Apps Script соответствующую публичную функцию: dashboardGetDashboardData, cashGetMoneyData, profitGetProfitData или capitalGetCapitalData.

   - выбранный период;
   - используемую дату среза;
   - компоненты изменённой формулы;
   - итоговое значение;
   - возможные ошибки или подстановки.
4. Для Cash Buffer проверь, что в периоде 01.01.2023–30.06.2023 результат близок к 144,4568 и положителен.
5. Для изменений интерфейса проверь, что CSS-правило не перебивается более поздним стилем.
6. Не публикуй веб-приложение без отдельного подтверждения пользователя.
```
